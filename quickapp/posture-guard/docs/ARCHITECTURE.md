# 架构设计文档 - 体态安全卫士

## 1. 系统概述

体态安全卫士采用分层架构设计，实现传感器数据采集、AI推理、隐私保护、安全存储的完整数据处理流水线。

## 2. 架构分层

### 2.1 传感器层 (Sensors Layer)

**职责**: 封装硬件传感器访问，提供统一数据接口

```
┌─────────────────────────────────────────┐
│           SensorInterface               │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐   │
│  │ AccDriver│ │GyroDriver│ │ HRDriver│   │
│  └─────────┘ └─────────┘ └─────────┘   │
│         ↓ Mock Mode Toggle ↓            │
│  ┌─────────────────────────────────┐    │
│  │        SensorMock               │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

**关键设计**:
- 抽象基类 `SensorInterface` 定义统一接口
- Mock模式支持模拟器测试，无需真实传感器
- 采样策略可动态切换 (active/static/night)

### 2.2 核心层 (Core Layer)

**职责**: AI推理引擎，实现体态识别

```
┌─────────────────────────────────────────────────┐
│                PostureEngine                     │
│  ┌──────────────┐    ┌──────────────┐           │
│  │FeatureExtractor│──→│PostureClassifier│        │
│  └──────────────┘    └──────────────┘           │
│         ↓                      ↓                 │
│  ┌──────────────┐    ┌──────────────┐           │
│  │ConfidenceFilter│  │ AdaptiveThreshold│        │
│  └──────────────┘    └──────────────┘           │
│         ↓                                         │
│  ┌──────────────┐    ┌──────────────┐           │
│  │ AlertTrigger │    │PowerOptimizer│            │
│  └──────────────┘    └──────────────┘           │
└─────────────────────────────────────────────────┘
```

**数据流**:
```
传感器数据 → 特征提取(250帧窗口) → 动态阈值分类 → 多帧确认(3帧) → 提醒触发
                                      ↑
                               自适应阈值更新
```

**关键算法**:
- **特征提取**: 滑动窗口 + DFT频谱分析 + 互补滤波姿态估计
- **分类器**: 优先级规则 + 动态阈值 + 持续时间计数
- **多帧确认**: 连续3帧置信度>0.8才触发异常
- **功耗优化**: 根据数据变化率动态调整推理间隔 (1-5秒)

### 2.3 隐私层 (Privacy Layer)

**职责**: 数据脱敏、加密、生命周期管理

```
┌─────────────────────────────────────────────────┐
│              Privacy Hub                         │
│  ┌──────────────┐    ┌──────────────┐           │
│  │Desensitizer   │    │DifferentialPrivacy│      │
│  │ - 时间戳模糊  │    │ - Laplace机制     │      │
│  │ - 心率区间化  │    │ - ε=0.1          │      │
│  │ - 坐标DP噪声  │    └──────────────┘           │
│  └──────────────┘                               │
│         ↓                                         │
│  ┌──────────────┐    ┌──────────────┐           │
│  │CryptoManager │    │KeyDerivation │           │
│  │ - AES-128/256│    │ - PBKDF2      │           │
│  │ - GCM模式    │    │ - Shamir 2/3  │           │
│  └──────────────┘    └──────────────┘           │
│         ↓                                         │
│  ┌──────────────┐    ┌──────────────┐           │
│  │LifecycleMgr  │    │ AuditLogger  │           │
│  │ - 热/温/冷/销毁│  │ - 哈希链防篡改│           │
│  └──────────────┘    └──────────────┘           │
└─────────────────────────────────────────────────┘
```

**脱敏规则**:
| 数据类型 | 脱敏方式 | 配置 |
|----------|----------|------|
| 时间戳 | 5分钟区间模糊 | 14:00-14:05 |
| 心率 | 5bpm区间化 | 72→70-75 |
| 坐标 | DP噪声 ε=0.1 | Laplace(10) |
| 步数 | 10步区间 | 1234→1230-1240 |

**加密分级**:
| 级别 | 算法 | 密钥来源 | 生命周期 |
|------|------|----------|----------|
| L1 | AES-128-GCM | HKDF派生 | 7-90天 |
| L2 | AES-256-GCM | 独立派生 | 1-30天 |
| L3 | AES-256-GCM | Shamir分片 | 24h强制销毁 |

### 2.4 存储层 (Storage Layer)

**职责**: 安全存储封装，批量写入优化

```
┌─────────────────────────────────────────────────┐
│             SecureStorage                        │
│  ┌─────────────────────────────────────────┐    │
│  │         Write Buffer (100 items)         │    │
│  └─────────────────────────────────────────┘    │
│         ↓ 30秒/满100条刷盘                       │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐        │
│  │ /l1/*.enc│ │ /l2/*.enc│ │ /l3/*.enc│        │
│  └──────────┘ └──────────┘ └──────────┘        │
└─────────────────────────────────────────────────┘
```

**写入流程**:
```
数据 → 脱敏检查 → 加密 → 缓冲区 → 批量刷盘 → 磁盘
```

### 2.5 事件总线 (EventBus)

**职责**: 模块间解耦通信

```javascript
// 事件类型
'sensor:data'      // 传感器数据
'sensor:error'     // 传感器错误
'engine:result'    // AI推理结果
'privacy:encrypted'// 数据加密完成
'storage:flush'    // 存储刷盘
'system:status'    // 系统状态
'app:background'   // 应用后台
```

## 3. 关键设计决策

### 3.1 为什么选择端侧AI而非云端?

- **隐私**: 原始传感器数据不离开设备
- **延迟**: 本地推理<50ms，云端需200ms+
- **可用性**: 无需网络，离线可用
- **功耗**: 减少无线通信开销

### 3.2 为什么使用差分隐私?

- **数学保证**: ε-差分隐私提供可证明的隐私保护
- **可用性**: 添加噪声后数据仍可用于统计分析
- **标准**: 差分隐私是业界认可的隐私保护标准

### 3.3 为什么使用Shamir分片?

- **抗单点故障**: 2-of-3分片，任一丢失不影响恢复
- **安全**: 1个分片无法还原密钥
- **可恢复**: 任意2个分片可恢复完整密钥

## 4. 性能优化策略

### 4.1 功耗优化

| 策略 | 实现 | 效果 |
|------|------|------|
| 自适应采样 | 根据运动强度切换50/20/10Hz | 降低30%采样功耗 |
| Duty-cycling | 静止时推理间隔延至5秒 | 降低50%推理功耗 |
| 批量存储 | 100条或30秒刷盘 | 降低80%存储I/O |

### 4.2 内存优化

- 滑动窗口使用Float32Array
- 大对象使用后及时置null
- 审计日志虚拟滚动

### 4.3 启动优化

- 非关键模块延迟初始化
- 隐私中心延后2秒加载

## 5. 容错设计

| 故障场景 | 降级策略 |
|----------|----------|
| 传感器超时(10s) | 自动切换Mock模式 |
| 存储空间>90% | 自动清理冷数据 |
| 加密异常 | 数据暂存内存缓冲 |
| 密钥分片丢失 | L3数据自动销毁 |
