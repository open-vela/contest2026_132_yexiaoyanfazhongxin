# 姿态守护 (Posture Guard) - OpenVela 手表端侧姿态识别快应用

## 一、作品简介

**姿态守护**是一款运行在 OpenVela 智能手表上的端侧姿态识别快应用。通过手表内置的 IMU 传感器（加速度计 + 陀螺仪）实时采集人体运动数据，使用轻量级 1D-CNN 模型在手表端完成推理，**无需云端支持**，即可识别 5 种常见人体姿态：

| 姿态 | 图标 | 说明 |
|------|------|------|
| 站立 | 🧍 | 静止站立，Z轴加速度≈9.8m/s² |
| 坐下 | 🪑 | 坐姿状态，加速度分布稳定 |
| 行走 | 🚶 | 周期性步态，频率1-3Hz |
| 抬手 | 🖐️ | 手臂抬起，X/Y轴加速度增大 |
| 摔倒 | ⚠️ | 短暂失重后冲击，需及时预警 |

### 技术亮点
- **端侧推理**：模型完全运行在手表本地，保护隐私，无网络依赖
- **轻量模型**：1D-CNN 仅 ~6,500 参数，float32 权重约 26KB
- **低功耗设计**：后台自动暂停传感器，智能采样率调节
- **模拟测试**：内置模拟传感器，无需真实硬件即可完整测试

## 六、模型部署到 OpenVela 端侧

### 6.1 模型架构

```
Input: [50, 6] (50帧 × 6轴)
    ↓
Conv1D(6→16, k=5) + ReLU + MaxPool(2)  → [25, 16]
    ↓
Conv1D(16→32, k=3) + ReLU + MaxPool(2) → [12, 32]
    ↓
Flatten → FC(384→5) → Softmax
    ↓
Output: [5] (5类姿态概率)
```

### 6.2 权重嵌入方式

当前模型权重直接嵌入在 `posture-model.js` 中（JavaScript 数组），适用于快速原型验证。

### 6.3 真实模型训练与部署流程

```
1. 数据采集: 在手表上采集各姿态的IMU数据 → 导出CSV
2. 数据预处理: 滑动窗口切分 + Z-score标准化
3. 模型训练: 使用PyTorch训练1D-CNN
4. 模型量化: float32 → int8 (体积缩小4倍)
5. 权重导出: 转为JSON/TypedArray格式
6. 集成部署: 替换posture-model.js中的权重数组
```

### 6.4 训练代码参考 (Python)

```python
import torch
import torch.nn as nn

class PostureCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv1d(6, 16, kernel_size=5, padding=2)
        self.conv2 = nn.Conv1d(16, 32, kernel_size=3, padding=1)
        self.pool = nn.MaxPool1d(2)
        self.fc = nn.Linear(32 * 12, 5)

    def forward(self, x):  # x: [batch, 6, 50]
        x = self.pool(torch.relu(self.conv1(x)))  # [batch, 16, 25]
        x = self.pool(torch.relu(self.conv2(x)))  # [batch, 32, 12]
        x = x.view(x.size(0), -1)                 # [batch, 384]
        return self.fc(x)                          # [batch, 5]
```

## 七、边界处理

### 7.1 传感器权限

```javascript
// 在sensor-manager.js中处理传感器订阅失败
try {
  sensor.subscribeAccelerometer({ callback: onData });
} catch (e) {
  // 权限被拒绝或传感器不可用
  this._accelAvailable = false;
  // 自动切换到模拟模式
}
```

### 7.2 采样频率控制

- 可选频率：25Hz / 50Hz / 100Hz
- 默认50Hz，平衡精度和功耗
- 用户可在设置页动态调整

### 7.3 异常数据过滤

1. **NaN/Infinity检测**：逐帧检查所有6个通道
2. **范围检查**：加速度 > ±39.2m/s² 或陀螺仪 > ±40rad/s 判定为异常
3. **Z-score异常值**：超出3倍标准差的数据用均值替代
4. **连续错误监控**：连续10帧异常触发传感器重连

### 7.4 低内存保护

- 环形缓冲区固定大小(50帧)，不会无限增长
- 推理临时数组及时释放
- UI刷新频率限制(200ms间隔)
- 后台自动暂停所有采集和推理

### 7.5 功耗优化

| 状态 | 行为 | 功耗 |
|------|------|------|
| 前台运行 | 50Hz采样 + 500ms推理 | 中 |
| 页面隐藏 | 暂停传感器和推理 | 极低 |
| 模拟模式 | 无真实传感器功耗 | 低 |

| 模拟姿态 | 传感器特征 | 预期识别 |

## 十、已知限制与改进方向

1. **模型精度**：当前使用随机初始化权重，需要真实数据训练后替换
2. **姿态类别**：可扩展更多姿态（跑步、上下楼梯等）
3. **个性化**：可增加用户校准功能，提高个体识别准确率
4. **历史分析**：可增加姿态统计图表和健康报告
5. **告警通知**：摔倒检测可触发震动告警和紧急联系人通知
